# Building and releasing the engine

Both plugins run `rsemble`, a semantic code search engine whose source is in [`engine/`](../engine): the crates
`rsemble-core` (chunking, embeddings, hybrid retrieval and ranking, a Rust port of
[MinishLab Semble](https://github.com/MinishLab/semble)) and `rsemble` (file listing, persisted indexes, the CLI and
the `rsemble serve` MCP server the plugins start). Both are MIT-licensed; see their `LICENSE` and `NOTICE` files.

## Where the source comes from

The crates are developed in the Decode repository and mirrored here by
[`scripts/sync-engine.py`](../scripts/sync-engine.py). It copies the committed crates of a given Decode commit,
writes `engine/Cargo.toml` and derives `engine/Cargo.lock` from Decode's
lock file, so the release builds the dependency versions Decode tests. Edit the crates in Decode, then:

```bash
python3 scripts/sync-engine.py --decode '/path/to/decode-checkout' --rev HEAD
(cd engine && cargo test --locked)
```

Decode reads and writes the same index files as `rsemble`: the model in `<storage>/semble-model-<revision>`, one
index per folder in `<index dir>/<revision>/<sha256 of the folder path>.bin`, and the same listing rules. Decode's
test suite checks that the two agree.

## Building locally

```bash
cd engine
cargo build --locked --release --bin rsemble
target/release/rsemble --help
```

## Releases

[`.github/workflows/release.yml`](../.github/workflows/release.yml) runs on a `v*` tag push (or by hand for an
existing tag). It tests the engine on macOS arm64 and Linux x86_64, builds `rsemble` for

```text
rsemble-aarch64-apple-darwin
rsemble-x86_64-apple-darwin
rsemble-x86_64-unknown-linux-gnu
rsemble-aarch64-unknown-linux-gnu
```

and publishes them with `LICENSE`, `NOTICE`, `THIRD-PARTY-LICENSES.txt` (generated by cargo-about from
`engine/Cargo.lock`, plus the MIT license of the vendored Vue parser) and `SHA256SUMS` over all of them.

To release: bump both plugin manifests (`.claude-plugin` and `.codex-plugin`, including the versioned Codex cache
path), the Claude marketplace's `metadata.version`, and `release=` in [`scripts/rsemble.sh`](../scripts/rsemble.sh).
Run `python3 scripts/sync-launchers.py`, run the tests, commit, then tag and push the tag. Published release assets
are immutable; publish a new version rather than replacing bytes behind a tag.

## Windows

Not supported. The launchers are Bash scripts and the hooks use Bash, jq and ripgrep. Supporting Windows takes:
an `x86_64-pc-windows-msvc` job in the workflow (the engine is untested there), PowerShell or `.cmd` equivalents
of `rsemble.sh`, both `server.sh` files and `chats-server.sh` (or one small cross-platform launcher binary), Windows
paths for the shared data folder and for Decode's VS Code global storage
(`%APPDATA%\Code\User\globalStorage\ultra.decode`), and a Windows run of the launcher and hook tests. Under WSL
the Linux builds work as they are.
